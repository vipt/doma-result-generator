日本語

Doma 2のSELECT結果から、@Entity・@Column付きのJavaクラスを生成するEclipseプラグインです。JOINや集計など、テーブル単位では表せない検索結果に利用できます。

インストール

  1. Eclipseで ヘルプ → 新規ソフトウェアのインストール…（Help → Install New Software…）を開きます。
  2. 追加…（Add…）を選び、名前を Doma Result Generator、ロケーションを上の更新サイトURLにします。
  3. Doma Result Generatorを選択し、内容とライセンスを確認してインストールします。
  4. Eclipseを再起動します。以降は ヘルプ → 更新の確認（Help → Check for Updates）から更新できます。

更新サイトのZIPをダウンロードして、Add… → Archive…からインストールすることもできます。

できること

  • ExplorerのSQLファイル、またはSQLエディター上で右クリックし、Generate Doma Result Class…から列名と型を取得してクラスを生成。SQLエディターでは未保存のテキストバッファーも使用。
  • doma-genの生成APIでprivateフィールドとpublicのgetter/setterを生成。アノテーション・プロパティの型をimportし、短い型名で出力。
  • 接続プロファイルをワークスペース内で共有し、別プロジェクトでも選択して利用。前回の選択とPackageはプロジェクトごとに保持。パスワードの暗号化保存は任意。
  • Driver JARs → Download...で主要7種類のDBのJDBCドライバーを取得。検証済みJARをワークスペース内で再利用できます。
  • name.propertiesの正規表現で、名前に一致するプロパティのJava型を指定。
  • Metadata SQL → SQL syntaxでコメント・文字列のDB別の規則を選択。JDBC URLによる自動判別、FOR UPDATE付きSELECTにも対応。
  • Doma本体でテンプレートを処理してから、公式doma-genのResultSetMetaReaderで列情報を取得します。ダミー引数は自動で用意し、引数入力と元SQLの書き換えは不要です。
  • SQLの解析・条件判定・ループ・埋め込み変数・不要なAND/ORの除去は、変更していないDoma標準の処理を使用。値のバインドにもDomaを使います。
  • DAOの宣言型とSQLのテスト値からダミー引数を作成。DTO・定数はプロジェクトのクラスパスから自動で読み込みます。先にプロジェクトをビルドしてください。
  • PreviewではSELECTを実行して列情報を取得します。0件の結果でも生成できます。取得列が引数で変わるSQLでは、ダミー値で選ばれた経路のProposed Javaを確認してください。
  • SQL ServerのWITHで始まるCTEにも対応。ラッパーやSET FMTONLYは挿入しません。
  • 既存ファイルがある場合、Preview時にMerge／Overwrite／Cancelを選択。マージは手動コードを保持し、上書きはファイル全体を生成し直します。どちらも差分を確認して最終ボタンを押すまで保存しません。
  • マージでは管理タグのない既存フィールドも、型とDomaの列対応が一致すればそのまま利用。コンストラクター・コメント・equalsなどを保持し、新しい列だけを追加できます。上書きでは手動メンバーとコメントも置き換わります。
  • 接続待ちでも進捗ダイアログのCancelでPreviewの待機を中止。Preview timeout (seconds)で待ち時間の上限を設定（初期値30秒）。遅れて返った結果は適用しません。

CREATED_DATETIMEから生成するcreatedDatetimeのようなJavaのプロパティ名に照合し、上から最初に一致したルールをJDBCの推定型より優先します。

テーブルからDAO・Entity・SQLを生成

  1. ExplorerでJavaプロジェクトやフォルダーを右クリックし、Generate Doma DAO, Entity and SQL...を選びます。Projectメニューからも起動できます。
  2. 既存のConnection profileを選択し、Java／SQLの出力先とEntity／DAOのパッケージを指定します。EntityListener、name.properties、既存のdoma-genのFreeMarkerテンプレートディレクトリーも指定できます。
  3. Tables → Load tablesでテーブルを読み込み、生成対象にチェックを入れます。スキーマ・View表示・文字列フィルターで対象を探せます。
  4. Previewを押すと、Proposed filesの左にチェック付きツリー、右に選択ファイルの内容を表示します。境界のドラッグで幅を調整できます。新規はCreate、既存は初期値をMergeにします。
  5. 生成・更新するファイルにチェックし、Merge checked／Overwrite checkedでチェックした既存ファイルだけに操作を一括指定できます。親のチェックは配下へ反映し、一部選択は中間状態で表示します。未チェックは変更しません。
  6. Compare checked changes...でチェック対象だけの差分を確認後、Generate checked filesで保存します。チェックや操作を変えたら再比較が必要です。PreviewとCancelでは生成ファイルを書き込みません。

公式doma-gen 2.28.0のテーブルメタデータ取得・記述ファクトリー・FreeMarker生成処理を使用します。Gradleの実行は不要です。既存のdao.ftl・entityListener.ftl・entity.ftl・*.sql.ftlを利用でき、主キー・Version列・自動採番・型変換も公式処理に従います。主キーがないテーブルには既定のSELECT SQLは生成しません。DBのデータは更新しません。

JavaのMergeは手動追加メンバーやコメントを保持します。初回は既存メンバーとクラスのアノテーションを保持し、足りないアノテーション・メンバー・importを追加します。前回の生成結果がない既存SQLは、そのまま保持します。以降はワークスペース内に保存した前回の生成結果を使ってマージし、競合があれば更新を止めます。Overwriteは手動コードとコメントも含めて置き換えるため、差分を確認してください。

接続プロファイルはSELECT結果生成と共通です。パッケージ・出力先などのテーブル生成設定もプロジェクトごとに保持します。カスタムテンプレートとスキーマの扱い、マージの範囲は日本語READMEに記載しています。

FTLテンプレートの編集

  1. テーブル生成画面のConfiguration → Edit templates...を開きます。未指定ならプロジェクト内のdoma-gen-templatesを使用します。
  2. Copy missing defaultsでEntity・DAO・Listener・SQL・共通のlib.ftlをコピーできます。既存のFTLは上書きしません。
  3. ファイルを選択して編集し、SaveでUTF-8保存します。FreeMarkerの構文検査、未保存編集の確認、外部変更のReload、New...でのFTL追加に対応します。
  4. 閉じてもう一度Previewを押し、生成内容と差分を確認します。保存した変更をそのまま読み直します。

FTLの編集にDB接続は不要です。明示的に保存・追加・コピーしたFTLは、生成画面をCancelしても残ります。別のEclipseエディターの未保存編集や、読み込み後のディスク上の変更を上書きしません。詳しい手順は日本語READMEをご覧ください。

name.propertiesの編集

SELECT結果生成のType mappings (optional)と、テーブル生成のname.properties (optional)で、Browse...横のEdit...から設定を編集できます。未指定ならプロジェクト直下のname.propertiesを開き、ファイルがない場合はSaveで新規作成します。

.*Datetime$=java.time.LocalDateTimeなどのルールを編集して保存し、閉じてPreviewを押し直すと反映します。正規表現・型名の構文チェック、コメントと順序を保持するUTF-8保存、外部変更のReload、未保存編集と外部変更の保護に対応します。編集にはDB接続が不要で、保存済み設定は生成のCancel後も残ります。詳しい編集手順も参照してください。

JDBCドライバーをダウンロード

  1. SELECT結果生成またはテーブル生成の接続設定で、Driver JARs → Download...を押します。
  2. DBとバージョンを選び、互換性の説明・取得するJAR・ベンダーのライセンスを確認します。
  3. Download and useでMaven Centralから取得し、サイズ・SHA-256・JAR内容の確認後にDriver JARsとDriver classへ反映します。必須の依存JARも取得します。
  4. 接続URL・ユーザー名・パスワードを確認し、Previewします。共有プロファイルの変更はUpdate profileで保存します。

対応カタログ（2026-11-26確認）：Oracle ojdbc11 23.26.4.0.0、SQL Server 13.6.2.jre11、PostgreSQL 42.7.15、MySQL 26.10.0／9.7.0、MariaDB 4.0.0／3.5.11、Db2 LUW 12.1.5.0、H2 2.5.252。MySQL 26.10はサーバー8.4以降、9.7は8.0以降向けです。MariaDB 4.0はTLSの既定がverify-fullのため、接続先に合う版と設定を選んでください。

取得先はHTTPSのMaven Centralです。DBの接続情報は送りません。URLとユーザー名は保持し、ドライバークラスが変わる場合はパスワードをクリアします。同じクラスなら保持します。JARはワークスペースのメタデータ内に保存し、再利用時にも照合します。画面を開くだけではダウンロードせず、登録済みドライバーを自動更新しません。

Keep additional JARs already listedで手動指定のウォレット・認証用JARなどを保持できます。選んだドライバーと付属依存JARの既知の旧版は置き換えます。高度な認証やDb2のライセンス用JAR・ネイティブライブラリーなどは別途必要な場合があります。別バージョンは従来のBrowse...でも指定できます。

プロキシはEclipseのGeneral → Network Connectionsを利用します（サービスが使えない場合はJavaの設定）。Cancelとダウンロード用タイムアウトに対応し、途中の失敗では接続欄を変更しません。ダウンロードだけならDB接続は不要です。各版の依存JAR・ライセンス・検証範囲は日本語READMEをご覧ください。

接続プロファイルの使い方

  1. 既存の設定があるプロジェクトで生成ダイアログを開きます。Connection profile → Unregistered (project settings)に従来の接続情報を表示します。
  2. Save as...を押し、「開発DB」などの名前で登録します。表示中の接続設定・タイムアウト・パスワード保存の選択を引き継ぎ、再入力は不要です。
  3. 別プロジェクトでConnection profileから登録名を選びます。接続設定が一括で入り、次回からそのプロジェクトの前回選択を復元します。

共有設定の変更はUpdate profile、別の接続の登録はSave as...で確定します。ダイアログを閉じるだけでは共有設定を上書きしません。Package・Class name・出力先は共有しません。

Manage...で名前変更・削除とExport all... / Import...ができます。エクスポートには接続URL・ユーザー名・JARパスを含み、パスワードは含めません。インポート後はパスワードとローカルのJARパスを確認してください。同名の設定は名前に連番を付けて追加します。

macOSでパスワードを保存できない場合

保存時にConnection settings or the saved password could not be updated.と表示される場合、キーチェーンから暗号化用のマスターパスワードを取得できていない可能性があります。入力画面が出ないまま失敗する場合もあります。EclipseのログにOSXProviderのエラー（例：Result: -25300）がある場合は、次の手順を試してください。

  1. Eclipseの設定（通常⌘,）からGeneral → Security → Secure Storage → Passwordを開きます。
  2. Master password providersでOS X Keystore Integrationのチェックを外し、UI Promptを有効にしてApply and Closeを押します。
  3. 生成ダイアログでDBのPasswordを再入力し、Save password in Eclipse Secure Storageをオンにします。プロファイルではUpdate profileで保存します。未登録設定ではダイアログを閉じると保存し、Cancelでも保存します。
  4. 表示される画面で、Eclipseの保存情報を暗号化するためのマスターパスワードを設定または入力します。生成ダイアログを開き直して、Passwordが復元されることを確認します。

UI PromptでもSecure Storageへの暗号化保存を利用します。変更するのはマスターパスワードの取得方法です。設定はEclipse全体で新しく保存する情報に影響し、既存の保存情報は自動移行されません。Eclipse公式の設定説明と動作の説明も参照してください。

対応環境と現在の範囲

Eclipse 2023-12 / 4.30以降、Java 17以上を対象にしています。Java開発機能（JDT）、対象プロジェクトのDoma 2設定、JDBCドライバーを用意してください。

初期プレビュー版です。H2とDoma 2.57.0・doma-gen 2.28.0でテストしています。ダミー引数を自動で用意し、Doma本体でSQLを組み立ててからdoma-genでSELECTを実行し、列情報を取得します。DTO・定数は先にプロジェクトをビルドしてください。取得列が分岐するSQLはProposed Javaで確認してください。元SQLは変更しません。他DBの実機検証は今後の確認項目です。

English

An Eclipse plug-in that generates Doma 2 result entities from SELECT column metadata. Use it for joins, aggregates and projections that do not match a single table.

Install

  1. Open Help → Install New Software… in Eclipse.
  2. Click Add…. Enter Doma Result Generator and the update site URL above.
  3. Select Doma Result Generator, review the installation details and license, and complete the installation.
  4. Restart Eclipse. Use Help → Check for Updates for future updates.

You can also download the update-site ZIP and install with Add… → Archive….

Features

  • Right-click a SQL file in Explorer or inside its SQL editor and select Generate Doma Result Class…. SQL editors can use unsaved text buffers.
  • Generate private fields and public getters/setters through doma-gen's generation APIs, using imports and short annotation/property type names.
  • Override property types with ordered, regex-based name.properties rules.
  • Choose dialect-aware comment/string rules under Metadata SQL → SQL syntax, with automatic JDBC URL selection and support for locking SELECTs.
  • Doma processes the template before the official doma-gen ResultSetMetaReader describes its results. Dummy arguments are supplied automatically; no argument input or source SQL edits are needed.
  • Unmodified Doma parsing, expression evaluation, IF/FOR processing, embedded directives and redundant AND/OR removal. Doma also binds typed dummy values.
  • Dummy values use DAO parameter types and SQL test literals. DTOs and constants load from the project's runtime classpath automatically; build the project first.
  • Preview executes the SELECT and reads metadata even for an empty result. If arguments change projected columns, review Proposed Java for the path selected with dummy values.
  • Use SQL Server CTEs starting with WITH, without injected wrappers or SET FMTONLY preambles.
  • If the file exists, choose Merge, Overwrite or Cancel when pressing Preview. Merge retains custom code; Overwrite regenerates the entire file. Both show a read-only comparison before the final action saves the file.
  • Merge reuses existing unmarked fields when types and Doma column mappings match, keeping constructors, comments and custom methods unchanged while adding new columns. Overwrite removes existing custom members and comments.
  • Share named connection profiles across projects in one workspace. Remember each project's last profile and Package, with optional encrypted password storage in Eclipse Secure Storage.
  • Download JDBC drivers for seven major databases with Driver JARs → Download... and reuse verified JARs across workspace projects.
  • Cancel the preview wait from its progress dialog even while connecting. Set Preview timeout (seconds) to limit the wait (default: 30 seconds). Late results are discarded.

Generate DAO, Entity and SQL from tables

  1. Select a Java project or folder in Explorer and choose Generate Doma DAO, Entity and SQL.... It is also available from the Project menu.
  2. Reuse a connection profile and choose Java/SQL destinations and entity/DAO packages. Optionally select an EntityListener, name.properties and your existing doma-gen FreeMarker template directory.
  3. Choose Tables → Load tables and check the tables to generate. Schema patterns, views and a text filter help narrow the list.
  4. Choose Preview. Proposed files displays a checkbox tree on the left and the selected file's contents on the right, with a draggable divider. New files use Create; existing files default to Merge.
  5. Check files to generate/update. Merge checked / Overwrite checked affects only checked existing files. Parent checks include descendants and partial selections are indeterminate. Unchecked files are skipped.
  6. Inspect Compare checked changes..., then select Generate checked files. Changing checks/actions requires comparison again. Preview and Cancel do not write generated files.

Uses official doma-gen 2.28.0 table metadata, descriptor factories and FreeMarker generation; Gradle is not required. Reuse dao.ftl, entityListener.ftl, entity.ftl and *.sql.ftl. Primary keys, version columns, identity and type mappings follow the official generator. Tables without primary keys have no default SELECT SQL. Database data is not modified.

Java merges retain custom members and comments; initial adoption keeps existing members/class annotations and adds missing annotations/members/imports. Existing SQL without a previous generation baseline is kept unchanged. Later merges use workspace-local baselines and stop on conflicts. Overwrite replaces entire files, including custom code/comments. Reuses SELECT generation connection profiles and remembers table-generation defaults per project. See the README for templates, schema handling and merge limits.

Edit FTL templates

  1. Open Configuration → Edit templates... in the table generator. An empty directory field uses doma-gen-templates in your project.
  2. Copy missing defaults adds editable Entity/DAO/Listener/SQL templates and shared lib.ftl. Existing FTL files are kept.
  3. Select a file, edit it and Save in UTF-8. Supports FreeMarker syntax validation, unsaved-change prompts, Reload for external changes and New... for additional templates.
  4. Close the editor and choose Preview again to load saved changes and inspect the generated output/differences.

No database connection is needed to edit templates. Explicit template saves/additions/copies remain if the generator is later canceled. Unsaved Eclipse editor buffers and on-disk changes since loading are protected from overwriting. See the README for details.

Edit name.properties

Choose Edit... beside Browse... under Type mappings (optional) in the SELECT result generator or name.properties (optional) in the table generator. An empty path opens name.properties in the project root; a missing file is created only when you Save.

Edit a rule such as .*Datetime$=java.time.LocalDateTime, save, close and choose Preview again. Includes regex/type-name syntax checks, UTF-8 text preserving comments/order, Reload and protection for unsaved Eclipse buffers or external edits. No database connection is needed to edit; explicit saves remain after canceling generation. See the editing guide.

Download JDBC drivers

  1. In either generator's connection panel, select Driver JARs → Download....
  2. Choose a database/version and review its compatibility notes, included JARs and vendor license.
  3. Select Download and use. HTTPS downloads from Maven Central are checked against pinned sizes, SHA-256 hashes and JAR contents before filling Driver JARs and Driver class. Required dependency JARs are included.
  4. Check the JDBC URL and credentials, then Preview. Select Update profile to persist shared profile changes.

Catalog checked 2026-11-26: Oracle ojdbc11 23.26.4.0.0; SQL Server 13.6.2.jre11; PostgreSQL 42.7.15; MySQL 26.10.0 / 9.7.0; MariaDB 4.0.0 / 3.5.11; Db2 LUW 12.1.5.0; H2 2.5.252. MySQL 26.10 requires server 8.4+, whereas 9.7 supports 8.0+. MariaDB 4.0 defaults to TLS verify-full; choose settings compatible with your server.

Database connection details are never sent to the repository. URL/username stay unchanged; changing the driver class clears the password, while keeping the same class retains it. JARs are cached in workspace metadata and verified before reuse. Opening the generator does not download or upgrade drivers automatically.

Keep additional JARs already listed preserves manual wallet/authentication JARs while replacing recognizable old copies of the selected driver and its included dependencies. Advanced authentication, Db2 license libraries and native libraries may need separate installation. Browse... remains available for other driver versions.

Downloads use Eclipse's General → Network Connections proxy service when available, otherwise Java networking settings. Cancel and a separate download timeout leave connection fields unchanged on failure. Downloading alone requires no database connection. See the README for dependencies, license links and verification limits.

Using connection profiles

  1. Open the generator in a project with saved settings. Connection profile → Unregistered (project settings) shows its previous connection.
  2. Select Save as... and name it, for example Development. The displayed connection settings, timeout and password-saving choice are retained without re-entry.
  3. In another project, select that name under Connection profile to fill its connection settings. Each project restores its last selection on subsequent openings.

Save shared edits with Update profile, or use Save as... for a separate connection. Closing the generator does not overwrite shared profiles. Package, class name and output location are not shared.

Manage... offers rename, delete and Export all... / Import.... Exports include connection URLs, usernames and JAR paths, and exclude passwords. Re-enter passwords and check local JAR paths after importing. Name collisions receive a numbered suffix.

macOS: password saving fails

If saving shows Connection settings or the saved password could not be updated., Eclipse may be unable to retrieve its encryption master password from the macOS keychain. This can fail without a prompt. If the Eclipse log contains an OSXProvider error, such as Result: -25300, try these steps:

  1. Open Eclipse settings/preferences (usually ⌘,), then General → Security → Secure Storage → Password.
  2. Under Master password providers, clear OS X Keystore Integration, enable UI Prompt, and select Apply and Close.
  3. In the generator, re-enter the database Password and select Save password in Eclipse Secure Storage. Select Update profile for a profile. For unregistered settings, close the dialog; Cancel also saves them.
  4. In the prompt, create or enter the master password for encrypting Eclipse's saved information. Reopen the generator to confirm the database Password is restored.

UI Prompt still uses encrypted Eclipse Secure Storage. Only the way Eclipse obtains the master password changes. The setting affects newly saved information throughout Eclipse; existing entries are not migrated automatically. See the official preferences guide and how Secure Storage works.

Requires Eclipse Java IDE 2023-12 / 4.30+, Java 17+, a Doma 2 project and a JDBC driver.

Initial preview. Tests use H2, Doma 2.57.0 and doma-gen 2.28.0. Automatic dummy arguments feed Doma's standard parser/evaluator/SQL builder, then the official generator executes the prepared SELECT and reads result metadata. Source SQL and the displayed template stay unchanged. Build the project for DTOs/constants; unsupported constructors, dependencies or standard Doma syntax produce an error. Projection-dependent templates describe one selected path. No custom branch selection, SQL repair or raw-SQL fallback is added. Database-specific checks remain open.

日本語

Doma 2のSELECT結果から、@Entity・@Column付きのJavaクラスを生成するEclipseプラグインです。JOINや集計など、テーブル単位では表せない検索結果に利用できます。

インストール

  1. Eclipseで ヘルプ → 新規ソフトウェアのインストール…（Help → Install New Software…）を開きます。
  2. 追加…（Add…）を選び、名前を Doma Result Generator、ロケーションを上の更新サイトURLにします。
  3. Doma Result Generatorを選択し、内容とライセンスを確認してインストールします。
  4. Eclipseを再起動します。以降は ヘルプ → 更新の確認（Help → Check for Updates）から更新できます。

更新サイトのZIPをダウンロードして、Add… → Archive…からインストールすることもできます。

できること

  • ExplorerのSQLファイル、またはSQLエディター上で右クリックし、Generate Doma Result Class…から列名と型を取得してクラスを生成。SQLエディターでは未保存のテキストバッファーも使用。
  • doma-genの生成APIでprivateフィールドとpublicのgetter/setterを生成。アノテーション・プロパティの型をimportし、短い型名で出力。
  • 接続プロファイルをワークスペース内で共有し、別プロジェクトでも選択して利用。前回の選択とPackageはプロジェクトごとに保持。パスワードの暗号化保存は任意。
  • name.propertiesの正規表現で、名前に一致するプロパティのJava型を指定。
  • Metadata SQL → SQL syntaxでコメント・文字列のDB別の規則を選択。JDBC URLによる自動判別、FOR UPDATE付きSELECTにも対応。
  • WHERE／HAVING内の入れ子の/*%if ...*/・/*%end*/はSQLを書き換えずに利用。すべての検索条件本文とテスト値を使い、列情報を取得します。
  • %if/%elseif/%elseの構文はDoma本体で解析し、独自の対応句チェックは行いません。分岐ごとの列名・順序・JDBC型が一致すれば生成します。同じ条件はUNION内でも同じ分岐を選び、独立した条件は最大64通りまで確認します。
  • Doma本体のSQLパーサー・ビルダーでSQLを組み立て、サブクエリ内も含めてWHERE ANDなどを正規化。実行時引数の代わりにテスト値を使います。
  • SQL ServerのWITHで始まるCTEも、そのまま利用。JDBCのメタデータ取得時に必要な文の区切りを内部で補います（エラー319への対応）。
  • 既存クラスは Preview → 差分比較 → Updateで更新。手動メソッドやコメントを保持し、衝突がある場合は更新を停止。
  • 接続待ちでも進捗ダイアログのCancelでPreviewの待機を中止。Preview timeout (seconds)で待ち時間の上限を設定（初期値30秒）。遅れて返った結果は適用しません。

CREATED_DATETIMEから生成するcreatedDatetimeのようなJavaのプロパティ名に照合し、上から最初に一致したルールをJDBCの推定型より優先します。

接続プロファイルの使い方

  1. 既存の設定があるプロジェクトで生成ダイアログを開きます。Connection profile → Unregistered (project settings)に従来の接続情報を表示します。
  2. Save as...を押し、「開発DB」などの名前で登録します。表示中の接続設定・タイムアウト・パスワード保存の選択を引き継ぎ、再入力は不要です。
  3. 別プロジェクトでConnection profileから登録名を選びます。接続設定が一括で入り、次回からそのプロジェクトの前回選択を復元します。

共有設定の変更はUpdate profile、別の接続の登録はSave as...で確定します。ダイアログを閉じるだけでは共有設定を上書きしません。Package・Class name・出力先は共有しません。

Manage...で名前変更・削除とExport all... / Import...ができます。エクスポートには接続URL・ユーザー名・JARパスを含み、パスワードは含めません。インポート後はパスワードとローカルのJARパスを確認してください。同名の設定は名前に連番を付けて追加します。

macOSでパスワードを保存できない場合

保存時にConnection settings or the saved password could not be updated.と表示される場合、キーチェーンから暗号化用のマスターパスワードを取得できていない可能性があります。入力画面が出ないまま失敗する場合もあります。EclipseのログにOSXProviderのエラー（例：Result: -25300）がある場合は、次の手順を試してください。

  1. Eclipseの設定（通常⌘,）からGeneral → Security → Secure Storage → Passwordを開きます。
  2. Master password providersでOS X Keystore Integrationのチェックを外し、UI Promptを有効にしてApply and Closeを押します。
  3. 生成ダイアログでDBのPasswordを再入力し、Save password in Eclipse Secure Storageをオンにします。プロファイルではUpdate profileで保存します。未登録設定ではダイアログを閉じると保存し、Cancelでも保存します。
  4. 表示される画面で、Eclipseの保存情報を暗号化するためのマスターパスワードを設定または入力します。生成ダイアログを開き直して、Passwordが復元されることを確認します。

UI PromptでもSecure Storageへの暗号化保存を利用します。変更するのはマスターパスワードの取得方法です。設定はEclipse全体で新しく保存する情報に影響し、既存の保存情報は自動移行されません。Eclipse公式の設定説明と動作の説明も参照してください。

対応環境と現在の範囲

Eclipse 2023-12 / 4.30以降、Java 17以上を対象にしています。Java開発機能（JDT）、対象プロジェクトのDoma 2設定、JDBCドライバーを用意してください。

初期プレビュー版です。H2とDoma 2.57.0で生成・更新処理をテストしています。他DBはJDBCドライバーの実行前メタデータ取得に依存します。条件式やアプリケーションのJavaコードは評価せず、生成用アダプターが選ぶ分岐とテスト値で列情報を取得します。列情報が異なる場合や64通りを超える場合、繰り返し値が必要なループ、埋め込み・リテラル変数はMetadata SQLで対象のSELECTを指定します。構文はDoma本体で判定し、単純な/*%expand*/は自動変換します。DBエラーはError details...でORA番号・失敗段階を確認できます。旧版クラスの生成元が不明なフィールドは削除せず残します。比較画面の手動操作と、各DBでの検証は今後の確認項目です。

English

An Eclipse plug-in that generates Doma 2 result entities from SELECT column metadata. Use it for joins, aggregates and projections that do not match a single table.

Install

  1. Open Help → Install New Software… in Eclipse.
  2. Click Add…. Enter Doma Result Generator and the update site URL above.
  3. Select Doma Result Generator, review the installation details and license, and complete the installation.
  4. Restart Eclipse. Use Help → Check for Updates for future updates.

You can also download the update-site ZIP and install with Add… → Archive….

Features

  • Right-click a SQL file in Explorer or inside its SQL editor and select Generate Doma Result Class…. SQL editors can use unsaved text buffers.
  • Generate private fields and public getters/setters through doma-gen's generation APIs, using imports and short annotation/property type names.
  • Override property types with ordered, regex-based name.properties rules.
  • Choose dialect-aware comment/string rules under Metadata SQL → SQL syntax, with automatic JDBC URL selection and support for locking SELECTs.
  • Use nested /*%if ...*///*%end*/ filters in WHERE/HAVING without editing SQL. Column metadata uses all filter bodies and test literals.
  • Parse %if/%elseif/%else using Doma itself, without a separate plug-in clause validator. Generate when every branch returns the same column names, order and JDBC types. Repeated conditions stay consistent across UNION branches; independent choices are checked in up to 64 combinations.
  • Assemble SQL with Doma's own parser and builder, normalizing leading operators such as WHERE AND, including in subqueries. Test literals replace DAO runtime arguments.
  • Use SQL Server CTEs starting with WITH unchanged. The required statement separator is supplied internally for JDBC metadata lookup (error 319).
  • Review existing-class changes before Update, retaining handwritten methods and comments. Conflicts stop the update.
  • Share named connection profiles across projects in one workspace. Remember each project's last profile and Package, with optional encrypted password storage in Eclipse Secure Storage.
  • Cancel the preview wait from its progress dialog even while connecting. Set Preview timeout (seconds) to limit the wait (default: 30 seconds). Late results are discarded.

Using connection profiles

  1. Open the generator in a project with saved settings. Connection profile → Unregistered (project settings) shows its previous connection.
  2. Select Save as... and name it, for example Development. The displayed connection settings, timeout and password-saving choice are retained without re-entry.
  3. In another project, select that name under Connection profile to fill its connection settings. Each project restores its last selection on subsequent openings.

Save shared edits with Update profile, or use Save as... for a separate connection. Closing the generator does not overwrite shared profiles. Package, class name and output location are not shared.

Manage... offers rename, delete and Export all... / Import.... Exports include connection URLs, usernames and JAR paths, and exclude passwords. Re-enter passwords and check local JAR paths after importing. Name collisions receive a numbered suffix.

macOS: password saving fails

If saving shows Connection settings or the saved password could not be updated., Eclipse may be unable to retrieve its encryption master password from the macOS keychain. This can fail without a prompt. If the Eclipse log contains an OSXProvider error, such as Result: -25300, try these steps:

  1. Open Eclipse settings/preferences (usually ⌘,), then General → Security → Secure Storage → Password.
  2. Under Master password providers, clear OS X Keystore Integration, enable UI Prompt, and select Apply and Close.
  3. In the generator, re-enter the database Password and select Save password in Eclipse Secure Storage. Select Update profile for a profile. For unregistered settings, close the dialog; Cancel also saves them.
  4. In the prompt, create or enter the master password for encrypting Eclipse's saved information. Reopen the generator to confirm the database Password is restored.

UI Prompt still uses encrypted Eclipse Secure Storage. Only the way Eclipse obtains the master password changes. The setting affects newly saved information throughout Eclipse; existing entries are not migrated automatically. See the official preferences guide and how Secure Storage works.

Requires Eclipse Java IDE 2023-12 / 4.30+, Java 17+, a Doma 2 project and a JDBC driver.

Initial preview. Core generation and update tests use H2 and Doma 2.57.0. Other databases depend on pre-execution JDBC metadata support. A generation adapter selects branches and test literals without evaluating conditions or application code. Differing column metadata, more than 64 combinations, loops requiring iteration values and embedded/literal variables need a concrete SELECT in Metadata SQL. Doma owns syntax validation; simple /*%expand*/ is prepared automatically. Error details... reports Oracle numbers and failure stages. Uncertain unmarked legacy fields are retained. Manual comparison-dialog checks and database-specific validation remain open.

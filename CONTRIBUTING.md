# Contributing

Contributions are welcome under the [Apache License 2.0](LICENSE). By submitting a contribution, you agree that it may be distributed under that license. No CLA is currently required.

## Development

Use JDK 17+ and the included Apache Maven Wrapper, which pins Maven 3.8.6 for Tycho 3 compatibility. Set `JAVA_HOME` to that JDK if necessary. Run `./mvnw -f tests/pom.xml test` for the portable core and `./mvnw verify` for the complete Eclipse plug-in and update site (`mvnw.cmd` on Windows). Import `plugin` into Eclipse PDE for interactive development. Keep core code free of Eclipse and vendor JDBC dependencies. Add a targeted regression test for changes to metadata handling or source generation.

The root is a Tycho reactor. `tests` is intentionally a standalone Maven project: it compiles the core and merger source using Maven JDT libraries, without resolving a p2 target or launching Eclipse. `merge-tests` checks update snapshots, compiler validation, dirty buffers, encoding, local history, connection profiles and encrypted settings in a real Eclipse runtime. `plugin` holds the runtime, `feature` describes the installable feature, and `repository` builds a p2 site.

## Manual Eclipse acceptance checklist

Before a release, record the Eclipse version, Java runtime, operating system and JDBC driver version used for these checks:

1. Build with `./mvnw clean verify`. Install the update-site ZIP into a clean Eclipse Java IDE and restart. Confirm the feature is installed without unresolved bundle errors.
2. Open a Java project with Doma and annotation processing. Save a `.sql` file and confirm the context menu appears for a single SQL file in both supported explorers.
3. With a test database, preview a SELECT with JOINs, explicit aliases, nullable columns and an aggregate. Confirm correct field types and original labels. Run a DAO returning the generated class.
4. Generate into a source folder and a new package. Confirm the class opens in the Java editor. Add handwritten methods and comments, change SQL columns/types, and preview the same destination. Confirm the read-only comparison shows both versions and no file is changed before Update. Apply, check custom code/comments and local history, then preview again and confirm Update is disabled with no changes.
5. Change SQL, class name and source folder after preview. Confirm Generate stays disabled until the preview is refreshed.
6. Check Doma dynamic directives, unknown types, duplicate aliases, invalid JDBC credentials and missing driver JARs. Verify useful errors, with no password shown in messages or saved in ordinary preferences.
7. Cancel the dialog. Confirm no Java class or modified SQL file was written.
8. Validate resizing, keyboard navigation and password masking. Check Windows, Linux and macOS before claiming support for each platform.
9. Put `.*Datetime$=java.time.LocalDateTime` in a saved project-root `name.properties`. Reopen the generator and confirm the file is initially selected. Preview a `CREATED_DATETIME` column, confirm the override, then clear the file field and confirm JDBC mapping is restored. Try a malformed regex and confirm the line-number error. Change the selected mapping file and confirm Generate requires another preview.
10. Edit the target after Preview and confirm Update refuses to apply the stale proposal. Repeat with an unsaved editor and an externally changed file. Check a custom getter body, a removed field referenced by a helper, and an incompatible helper return type: confirm source is retained and an explanation appears. Verify a legacy unmarked class adopts matching members and retains uncertain old fields with a note. Cancel comparisons and the generator and verify no file changed.
11. Preview `SELECT /*%expand*/* FROM EMPLOYEE WHERE DEPARTMENT_ID IN /* ids */(0)` and an expansion with a literal join alias. Confirm metadata describes the intended table, Metadata SQL shows `*` or `alias.*`, and the saved template remains unchanged. On an Oracle JDBC failure, confirm the ORA number, vendor code, SQLState and operation stage appear in Error details, with no raw SQL or connection details.
12. Select Unregistered (project settings), enter connection settings and Package, cancel and reopen, then restart Eclipse: confirm JAR paths, driver class, URL, username and the exact Package text are restored per project. With Save password off, confirm Password is empty; opt in and confirm an encrypted Secure Storage entry restores it. Uncheck or clear Password, close and verify deletion. Change URL/user/driver and verify Password clears. Check unregistered settings in another project/workspace stay separate, embedded-credential URLs are not remembered, and denied Secure Storage access never falls back to plaintext. Check Cancel, window close and Generate retain project settings without changing SQL templates.
13. Generate a new class and update an older class with qualified types and package-visible fields: confirm owned fields become private, annotations and property types use imports, and handwritten code/comments remain. Check name collisions with explicit/static imports and nested manual types. Open a workspace SQL file in the SQL editor, right-click and confirm the generator appears. Use unsaved edits and confirm Preview uses them without saving the file; check Explorer still reads the saved file. Verify Java editors and unrelated views do not show the SQL generator.
14. Check `.SQL`/mixed-case menus and class names, UTF-8 BOM round trips, multiple wildcard imports and same-package/java.lang collisions. Change/remove a BigDecimal column and confirm its unused generated import is removed while manual code/Javadoc imports remain. Use reluctant/alternative mapping patterns and lookaheads containing `=`. Confirm SQL syntax auto-selection and overrides handle path comments, PostgreSQL nesting/E-strings, MySQL backslash modes and locking SELECTs without executing SQL. Verify merge/validation failures identify the correct stage.

15. Preview with an unreachable database or a test driver that deliberately blocks connecting. Confirm the progress dialog's Cancel returns promptly, settings remain editable and no Java file changes. Retry with valid settings. Set a short Preview timeout and confirm it ends the wait without a click; reopen and restart Eclipse to check the per-project value. Repeat during metadata lookup and connection cleanup. Confirm a late driver result is discarded, acquired connections are released and two unfinished attempts produce a bounded-capacity explanation instead of starting more workers.

16. Register existing unregistered settings with Save as, including an encrypted saved password, without retyping. Select the profile in a second project and restart Eclipse: confirm connection settings are shared, selections and Packages are separate, and source/class/SQL/mapping fields are not copied. Edit a shared profile and confirm only Update profile or Save as persists edits; Cancel leaves the shared settings unchanged. Check the discard prompt when switching with unsaved connection edits, and preview invalidation after switching. Rename a profile and verify selections and passwords survive. Delete it and verify its own secret is removed, other profiles are unaffected, and projects fall back to unregistered settings. Exercise Secure Storage read/write/delete failures and retry, duplicate names, scrolling and keyboard focus at a small window size. Export and import in another workspace: confirm UTF-8 settings survive, passwords are excluded, imported password saving is off, name collisions do not overwrite existing settings and local JAR paths can be corrected.

17. Preview an unchanged template with nested `%if`/`%end` filters, bind test literals and application enum/function expressions in comments. Check WHERE, HAVING, IN-list fragments, correlated subqueries, CTEs and UNION branches. Confirm filter comments remain in Metadata SQL, the saved file is untouched, columns match the test SQL and no SELECT execution/fetch API is called. Check `%expand` still works with filters. Conditions affecting projection/FROM, crossing SQL clauses or parenthesis/query scopes, else branches, loops and unmatched tags must stop with useful diagnostics. Verify quoted/commented directive-like text and SQL Server `@where`/`#where` identifiers cannot confuse clause tracking.

## Reporting compatibility

Report the database/server version, JDBC driver coordinates/version, Eclipse/Java/OS versions, redacted sample SQL, expected Java fields and whether `getMetaData()` works before execution. Do not include passwords, production rows, private hostnames or complete connection URLs.

Vendor-specific behavior must be handled by an explicit mapping/strategy and tested on that database before being advertised. Never silently fall back to `Object` or execute arbitrary templates to infer types.

## Publishing

The public repository is `vipt/doma-result-generator`; GitHub Pages serves `https://vipt.github.io/doma-result-generator/`. Configure **Settings → Pages → Source → GitHub Actions**. A push to `main` runs tests, assembles `_site` with `scripts/build_pages.py`, and deploys the Pages artifact. Pull requests do not deploy. `_site` contains the static `site` files, p2 metadata/features/plugins, a ZIP download and build provenance in `build.json`.

Keep root/plugin/feature license files synchronized and run the manual checks before a release. GitHub Releases are not created automatically: attach the generated repository ZIP when creating a versioned release. When changing the Maven project version, update the distribution archive path in `scripts/build_pages.py` and installation documentation as well.
